# M3: Hot Reload + Per-Route Plugin Chains — Design

**Date:** 2026-04-03  
**Status:** Approved  
**Milestone:** M3 of 6

---

## Goal

Make prismproxy dynamically reconfigurable without restarts, and make the plugin system route-scoped rather than global.

Two deliverables:
1. **Hot reload** — when `config.toml` changes on disk, the proxy reloads routes and plugins atomically, with zero dropped connections.
2. **Per-route plugin chains** — each `[[routes]]` entry carries its own plugin list; different routes can have different (or no) plugins.

---

## Architecture

### Atomic State Swap

Replace the two separate `Arc<Config>` + `Arc<PluginRuntime>` with a single `Arc<ArcSwap<AppState>>`:

```
AppState {
    routes: Vec<RouteState>,
}

RouteState {
    route: RouteConfig,       // path_prefix, upstream, timeout_ms
    runtime: PluginRuntime,   // pre-compiled plugins for this route
}
```

`server.rs` holds one `Arc<ArcSwap<AppState>>`. The accept loop clones the `ArcSwap` handle; each request calls `.load()` to get an immutable snapshot of current state. Lock-free, zero downtime.

### Hot Reload Task

A second `tokio::spawn` task runs alongside the accept loop. It polls the config file's `mtime` every 1 second via `tokio::time::interval`. On detected change:

```
read file → parse → validate → build AppState → arc_swap.store(Arc::new(new_state))
```

If any step fails (parse error, invalid address, plugin file missing), log a `warn!` and keep the previous state. On success, log `info!` with route/plugin counts.

No new crate dependency beyond `arc-swap = "1"`.

```
┌─────────────────────────────────────────┐
│  accept loop                            │
│  ArcSwap<AppState>.load() per request   │
└─────────────────────────────────────────┘
          ▲ atomic store
┌─────────────────────────────────────────┐
│  reload task (tokio::spawn)             │
│  poll mtime every 1s                    │
│  parse → validate → build → store      │
│  on error: warn! + keep previous state │
└─────────────────────────────────────────┘
```

## Config Format

`[plugins]` global section is removed. Each route optionally declares its own plugin list:

```toml
[server]
listen = "127.0.0.1:8080"
max_idle_connections = 10
timeout_ms = 30000

[[routes]]
path_prefix = "/api"
upstream = "127.0.0.1:3000"
plugins = ["./plugins/auth.wasm", "./plugins/rate.wasm"]

[[routes]]
path_prefix = "/"
upstream = "127.0.0.1:8000"
# no plugins field → empty chain, all requests pass through
```

Routes are still matched top-to-bottom; first prefix match wins.

### Breaking change

`PluginsConfig` and the global `[plugins]` key are removed. Any config using `[plugins]` must move plugin paths into the relevant `[[routes]]` entries.

## Request Flow

```
request arrives
  → state.load()                        // lock-free snapshot
  → find RouteState by path_prefix      // first match wins
  → RouteState.runtime.run_on_request() // run this route's plugins
  → if blocked → 403 Forbidden
  → else → proxy.forward(upstream)
```

The WASM ABI is unchanged: plugins still export `memory` + `on_request(method_ptr, method_len, path_ptr, path_len) -> i32`.

## New File: `src/state.rs`

Owns `AppState`, `RouteState`, and `build_state(config: Config) -> Result<AppState, ProxyError>`.

`build_state` iterates `config.routes`, compiles each route's plugins into a `PluginRuntime`, and returns a fully-initialized `AppState`. This is the single function called both at startup and on every successful reload.

## Error Handling

| Scenario | Behavior |
|---|---|
| Config file unreadable | `warn!` + keep previous state |
| TOML parse error | `warn!` + keep previous state |
| Invalid listen/upstream address | `warn!` + keep previous state |
| Plugin `.wasm` file not found | `warn!` + keep previous state |
| All of the above at startup | `Err(ProxyError)` → process exits with error message |

Startup is strict (fail fast). Runtime reloads are lenient (keep serving).

## File Map

| File | Action |
|---|---|
| `Cargo.toml` | Add `arc-swap = "1"` |

| `src/handler.rs` | Accept `Arc<ArcSwap<AppState>>`; call `state.load()` per request |
| `tests/common/mod.rs` | Update `test_config`, add `test_route_with_plugin` helper |
| `tests/plugins.rs` | Rewrite for per-route plugins |
| `tests/reload.rs` | New — hot reload integration tests |

## Tests

### Unit (`src/config.rs`)
- `route_with_plugins_parses` — `[[routes]]` with `plugins = [...]` deserializes correctly
- `route_without_plugins_defaults_empty` — missing `plugins` field defaults to `[]`

### Unit (`src/state.rs`)
- `build_state_with_no_plugins_succeeds` — routes with empty plugin lists build cleanly
- `build_state_with_missing_plugin_fails` — nonexistent plugin path returns `Err`

### Integration (`tests/plugins.rs`)
- `route_with_pass_all_plugin_passes` — plugin passes, upstream 200 returned
- `route_with_block_path_plugin_returns_403` — plugin blocks `/blocked`, returns 403
- `route_without_plugin_always_passes` — route with no plugins, all requests pass
- `two_routes_independent_plugin_chains` — `/api` has block plugin, `/pub` has none; each behaves correctly

### Integration (`tests/reload.rs`)
- `reload_adds_new_route` — proxy starts with config A, config B written to disk, after 1.5s new route responds
- `reload_invalid_config_keeps_previous_state` — invalid TOML written to disk, proxy keeps serving with old config
- `reload_changes_plugin_chain` — route starts with pass plugin, config reloads with block plugin, subsequent request gets 403
